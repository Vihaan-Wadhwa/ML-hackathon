# PathSnap Device 3 to Device 4 Integration Guide

**Document:** Device 4 (Evaluation & Visualization) Integration Specification  
**Producer:** Device 3 (Road Topology & Trajectory Reconstruction)  
**Consumer:** Device 4 (Backend Evaluation & Streamlit UI)  
**Package:** `modules/device3`

---

## 1. Import Statements

Device 4 can import Device 3's main reconstruction pipeline and supporting functions using either of the following sanctioned paths:

```python
# Standard repository import (from ML-hackathon root)
from modules.device3.decoder.reconstruction import reconstruct_trip, convert_timestamps_to_datetime
from modules.device3.graph.graph_builder import build_road_graph
from modules.device3.decoder.candidate_io import load_candidate_predictions, load_track

# Or isolated package import (when modules/device3 is on sys.path)
from decoder.reconstruction import reconstruct_trip, convert_timestamps_to_datetime
from graph.graph_builder import build_road_graph
from decoder.candidate_io import load_candidate_predictions, load_track
```

## 2. Graph Loading Interface

Each trip possesses its own dedicated road network. **Never combine road graphs from different trips.**

```python
road_graph, arc_lookup, graph_stats = build_road_graph(
    nodes_path="data/trips/<trip_id>/<trip_id>.nodes",
    arcs_path="data/trips/<trip_id>/<trip_id>.arcs"
)
```

* **`road_graph`** (`nx.MultiDiGraph`): Directed NetworkX multigraph where nodes have `longitude`, `latitude`, `node_id`, and directed edges are keyed by `arc_id` with attribute `length_m`.
* **`arc_lookup`** (`Dict[int, Tuple[int, int]]`): $O(1)$ constant-time lookup mapping `arc_id -> (from_node_id, to_node_id)`.
* **`graph_stats`** (`Dict[str, Any]`): Summary metadata including `total_nodes`, `total_directed_arcs`, and `total_directed_length_m`.

## 3. Input Data Schemas

### 3.1 Candidate Predictions DataFrame (`candidates_df`)

Device 3 natively supports candidate predictions generated by Device 2.

| Column | Type | Description |
| :--- | :---: | :--- |
| `trip_id` | `string` / `str` | Must match the current trip identifier. All rows must share this single `trip_id`. |
| `obs_idx` | `int64` / `int` | Zero-based observation index matching `.track` row indices. |
| `arc_id` | `int64` / `int` | Candidate road arc identifier. Must exist in `road_graph`. |
| `prediction_probability` *(or `match_probability`)* | `float64` | Raw probability score from classifier in range $[0.0, 1.0]$. |

*Additional feature or metadata columns in `candidates_df` are safely ignored.*

### 3.2 GPS Trajectory DataFrame (`track_df`)

Ingested from raw `<trip_id>.track` files via `load_track(track_path)` or constructed in memory:

| Column | Type | Description |
| :--- | :---: | :--- |
| `obs_idx` | `int64` / `int` | Zero-based observation sequence index $0, 1, \dots, T-1$. |
| `longitude` | `float64` | GPS longitude in degrees $[-180.0, +180.0]$. |
| `latitude` | `float64` | GPS latitude in degrees $[-90.0, +90.0]$. |
| `timestamp` | `float64` | Elapsed seconds since trip start (strictly monotonically increasing). |
| `trip_id` *(optional)* | `string` / `str` | If present, must match `trip_id` in `candidates_df`. |

## 4. `reconstruct_trip()` Usage

```python
reconstructed_df, diagnostics = reconstruct_trip(
    candidates_df=candidates_df,
    road_graph=road_graph,
    track_df=track_df,
    beta=5.0,                         # Network distance difference penalty scale in meters
    return_diagnostics=True,          # Set to True for telemetry / performance metrics
    arc_lookup=arc_lookup,            # Optional pre-built lookup for maximum performance
    shortest_path_cache=None          # Optional reusable dict cache for Dijkstra routing
)
```

If `return_diagnostics=False` (default), only `reconstructed_df` is returned.

---

## 5. Output DataFrame Schema

The returned `reconstructed_df` contains exactly 1 row per valid GPS observation in `track_df`:

| Column | Type | Description | Guarantee |
| :--- | :---: | :--- | :--- |
| `trip_id` | `string` | Single trip identifier | Matches input trip ID |
| `obs_idx` | `int64` | Sequential GPS row index | Preserves exact $0 \dots T-1$ order |
| `timestamp` | `float64` | Observation timestamp in seconds | Strictly identical to `track_df['timestamp']` |
| `latitude` | `float64` | Reconstructed snapped latitude | Lies on centerline of matched road arc |
| `longitude` | `float64` | Reconstructed snapped longitude | Lies on centerline of matched road arc |
| `arc_id` | `int64` | Matched directed road arc ID | Guaranteed to exist in `road_graph` |

### Optional Datetime Conversion
If Device 4 or the Streamlit UI requires localized timestamps rather than relative elapsed seconds:
```python
dt_df = convert_timestamps_to_datetime(
    reconstructed_df,
    start_datetime="2026-11-18 08:30:00",
    timezone="UTC"
)
# Adds a 'datetime' column (pd.Timestamp) without modifying 'timestamp'
```

## 7. Error Handling & Edge Cases

| Exception | Cause | Device 4 Recommended Action |
| :--- | :--- | :--- |
| `ValueError: candidates_df cannot be empty` | Empty predictions table passed | Skip trip or return status `"no_candidates"` |
| `ValueError: track_df cannot be empty` | Empty GPS track passed | Skip trip or return status `"empty_track"` |
| `ValueError: Mixed trip IDs found` | Candidate table contains $>1$ distinct trip IDs | Group candidates by `trip_id` before calling |
| `ValueError: trip_id mismatch` | `candidates_df` trip ID $\neq$ `track_df` trip ID | Verify data alignment |
| `ValueError: Candidate arc IDs not in road graph` | ML model predicted arcs from wrong region/trip | Fail with data integrity violation message |
| `ValueError: Temperature must be positive` | Invalid temperature parameter | Pass $T > 0$ (default $1.0$) |

### Automatic Edge-Case Protections Handled Internally by Device 3:
1. **Missing Observations (0 candidates):** Device 3 does NOT crash. It uses an accelerated axis-aligned bounding-box search (`find_nearest_candidate_arc`) to automatically find the nearest road arc within tolerance and continues Viterbi decoding.
2. **GPS Dropout ($> 5\text{s}$):** Effective $\beta$ dynamically scales with time gap $\Delta t$ ($\beta_{\text{eff}} = \beta \cdot \sqrt{\Delta t / \Delta t_{\text{median}}}$), allowing vehicles to traverse larger network gaps without zero-probability penalties.
3. **Disconnected Transitions:** Disconnected network pairs are floored at $\epsilon = 10^{-6}$ ($\ln(\epsilon) \approx -13.82$) in log-space, preventing $\ln(0) = -\infty$ arithmetic crashes while allowing continuous topological routes to strongly out-vote disconnected emissions.
